小微企业想用 AI 提效，卡点通常不是「模型够不够强」，而是账本、发票、客户名单要不要交出去。 下面这张表把四类方案放在同一把尺子上量：数据在哪、断网能不能用、AI 能不能动账、能不能换模型。

维度 云端 SaaS 记账 传统本地 ERP 通用 AI 助手 BOKI（开源 · 本地优先）
数据存在哪 厂商服务器 你的服务器 模型厂商 你的电脑，单文件
断网可用 ✗ 基本不可用 部分 依赖部署方式 ✗ 不可用 ✓ 记账 / 查账 / AI 全部照跑
库文件被拷走 — 多为明文 看配置 — SQLCipher 整库加密，打不开
AI 能直接改账吗 平台代劳，你看不见 基本没有 AI 只能聊，接不进账 只能出草稿，人点了才生效
模型可换 ✗ ✗ ✗ ✓ 本地 Ollama / llama.cpp / 内网 / 云端 API
外部 AI 可接 ✗ ✗ ✗ ✓ 只读 MCP，8 个查询工具
可审计 厂商说了算 有日志但封闭 无 ✓ 源码 + 操作日志 + AI 指令审计表
部署成本 订阅费，逐年涨 一次性实施 + 运维 按 token 计费 装完即用；模型本地跑，无 token 费
退出成本 导出有限，格式封闭 迁移靠厂商 无数据 SQLite 单文件 + 全量导出，随时拿走

① 模型你选

OpenAI 兼容协议，本地 / 内网 / 云端随时切换。换模型不改业务代码，也不改数据格式。

baseURL = http://127.0.0.1:9527/v1

② 数据不出门

整库加密、本地 OCR、本地语音识别、本地大模型。零云端依赖、零第三方 SDK、零埋点。

sqlcipher · no telemetry · no CDN

③ AI 只写草稿

草稿闸门 + 一次性令牌 + 只读 MCP。代码里没有「AI 直接过账」这条分支。

landing ∈ {draft, list, archive}
